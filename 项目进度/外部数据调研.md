# 外部数据调研：Kaggle "Top Beer Information"

> **调研日期**：2026-10-24
> **数据落盘**：`data/external/`（`.gitignore` 已忽略 `data/`，原始数据不进 git）
> **调研范围**：题目补充数据 <https://www.kaggle.com/datasets/stephenpolozoff/top-beer-information>
> **一句话结论**：数据集已成功获取，但它是 **BeerAdvocate 评论词频数据**，不含化合物、不含 0–6 感官评分、也不含附件 250 款酒的条码/酒名；只能做 **22 个风格级别**的外部校验与先验，不能做逐酒行级合并，不能替代 `1.csv`/`2.csv` 的化合物建模。

## 2. 数据规模与字段

### 2.1 主表 `beer_data_set.csv`

- 5,558 行（不含表头），21 列；UTF-8 带 BOM，字段有引号包围，`Description` 内可能含制表符、弯引号。
- 112 个 `Style`，112 个 `Style Key`；1,498 个 `Brewery`；`key` 5,558 个唯一值。
- 每款酒最多来自 25 条评论的词频，**不是**化学浓度，**不是** 0–6 评分，**不是**标准化后的连续值。

**10 个元数据列**：

| 列 | 含义 | 实测情况 |
|---|---|---|
| `Name` | 酒名 | 2 行缺失（Kvass / Monastyrskiy Kvas；Lager - European Pale / Stella Artois） |
| `key` | 数据集内部唯一键 | 5,558 个唯一值 |
| `Style` | BeerAdvocate 风格 | 112 种 |
| `Style Key` | 风格编号 | 112 种 |
| `Brewery` | 酒厂 | 1,498 个唯一值 |
| `Description` | 酒厂/页面描述文本 | 中位 125.5 字符，最短 6，最长 2,462；有尾部制表符 |
| `ABV` | 酒精度（% v/v） | 0–57.5，中位 6.0；19 行为 0，4 行 >20 |
| `Ave Rating` | BeerAdvocate 平均评分 | 1.27–4.83，均值 3.76 |
| `Min IBU` | 最小苦度 | 有 414 行为 0（疑似缺失 coded as 0） |
| `Max IBU` | 最大苦度 | 有 300 行为 0（疑似缺失 coded as 0） |

**11 个感官词频列**（原始计数，未归一化）：

| 列 | 范围 | 0 值占比 | 说明 |
|---|---:|---:|---|
| `Astringency` | 0–83 | 4.5% | 涩感 |
| `Body` | 0–197 | 3.3% | 酒体 |
| `Alcohol` | 0–139 | 5.8% | 酒精感 |
| `Bitter` | 0–150 | 4.5% | 苦 |
| `Sweet` | 0–263 | 3.2% | 甜 |
| `Sour` | 0–323 | 4.2% | 酸 |
| `Salty` | 0–66 | **60.6%** | 咸；词表只有 13 个词，信息量很低 |
| `Fruits` | 0–222 | 4.2% | 果味 |

| `Spices` | 0–184 | 8.9% | 香料 |

**总量与缺失（重要）**：

- 每款酒 11 列之和：中位 384，最小 0，最大 908。
- **132/5,558（2.4%）** 行 11 列全为 0（无评论/无命中词），不能当“零感官”使用。
- **383 行（6.9%）** 总词频 ≤50；**604 行（10.9%）** <100。低词频行只是“评论少”，不是“味道淡”，直接算均值会被评论量混杂。
- `Name` 缺失 2 行；其余 10 个元数据列完整。
- 1 组重复（`Name`+`Brewery` 相同）：Crazy Jackass Ale，`key` 568 与 594。
- `Salty` 60.6% 为 0，且词表只有 13 个词，后续不建议使用。

### 2.2 词表 `Beer Descriptors Simplified.xlsx`

| sheet | 维度 | 词条数（约） | 说明 |
|---|---|---:|---|
| Mouthfeel | Astringent / Body / Alcoholic | 64–97 | 口感类 |
| Taste | Bitter / Sweet / Sour / Salty | 13–128 | 味觉类；Salty 只有 13 个词 |
| Flavor And Aroma | Fruity / Hoppy / Spices / Malty | 99–209 | 风味/香气类 |

- 每个词条对应 `Impact=1`，CSV 的 11 列就是这些词表在评论中命中的次数。
- 词表是启发式构建的，含少量疑似酒名/拼写变体（例如 `blabaer`、`azrael`），说明它不是严格受控的感官词典；解释稀有词时要谨慎。
- **CSV 不含评论原文**，只给词频；因此无法重算、无法审计词频，也无法做文本级验证。这些列只能“按给定值使用”。

## 4. 与附件 250 款酒的连接方式

### 4.1 附件侧可用的键

| 键 | 位置 | 情况 |
|---|---|---|
| `beer` | `1.csv` / `4.csv` / `7.csv` / `8.xlsx` | 1–250，唯一，三表可对齐；**不是酒名** |
| `beer_id` | 同上 | EAN 条码；250 个唯一值。203/250 为 13 位；前缀 541（146）、542（48）、540（27）、871（10）等，以比利时条码为主；也有 32 个 8 位短码 |
| `tasting_category_fine` | `1.csv` 等 | 22 个粗风格标签（Blond、Tripel、Strong ale、Hoppy、Stout/Porter、Wheat、Amber、Brown、Pils/Lager、Lambic、Dubbel、Kriek、Saison、Christmas、Low/No alcohol、Fruitbeer、West Flanders ale、Brett/cofermented、Flanders old brown、Scotch、Brut、Faro） |
| ABV | `8.xlsx` → `Beer Prices` | 250/250 有值；`1.csv` 的 `ethanol..v.v.` 是 log10(%v/v)，`10^ethanol` 与 ABV 中位差 0.135、平均绝对差 0.439、最大绝对差 3.265，确认 ABV 列可用 |

**关键缺口**：附件 250 款酒的所有表里**没有酒名、没有酒厂**。这是无法与 Kaggle 逐行连接的根本原因。

### 4.2 Kaggle 侧可用的键

- `Name`、`Brewery`、`Style`、`key`。
- **没有条码**，没有与附件 `beer_id` 对应的字段。

### 4.3 行级连接：不可行，且不应硬做

- 没有共享键。
- 只用 ABV 匹配也不行：在“同一映射风格 + ABV ±0.3”条件下，每款附件酒在 Kaggle 中的候选数中位数为 **16**，最多 **407**；9/250 款酒无候选。放宽到 ±0.5，中位数 28、最多 544、5/250 无候选。这样匹配出来的“对应酒”基本是任意的。
- 用条码查 Open Food Facts 做了 5 个探针（见 §7.3）：3 个能查到品牌/品名，2 个 404；即使查到品牌，品名/ABV 也对不上 Kaggle 的具体酒款（例：Hoegaarden sans alcool 对不上 Hoegaarden Grand Cru/White Ale；Palm Na 对不上 Palm Speciale；Ciney 在 Kaggle 中无记录）。**0/5 能确认到具体酒款**。全量 250 个条码 + 模糊匹配可以作为未来工作，但本次不使用。
- **结论**：逐酒合并应放弃；采用风格级聚合，并在论文中明确说明“外部数据仅用于风格级外部校验，不做逐酒配对”。

### 4.4 风格级映射（可行）

把 Kaggle 的 112 个 BeerAdvocate 风格按语义归并到附件 22 个风格；采用**互斥映射**（每个 Kaggle 风格只归一个附件风格）：

- 覆盖：**96/112 个 Kaggle 风格**，**4,760/5,558 行（85.6%）**。
- 16 个未映射风格（无合适附件对应，或语义过窄）：`Bitter - English`、`Bitter - English Extra Special / Strong Bitter (ESB)`、`Bock - Maibock`、`Bock - Traditional`、`Bock - Weizenbock`、`Braggot`、`California Common / Steam Beer`、`Cream Ale`、`Gruit / Ancient Herbed Ale`、`Happoshu`、`Kvass`、`Rye Beer`、`Rye Beer - Roggenbier`、`Smoked Beer`、`Sour - Berliner Weisse`、`Sour - Gose`。
- 映射规则（摘要，便于复现）：
  - `Pils/Lager`：所有 `Lager - *` 与 `Pilsner - *`，但 `Lager - India Pale Lager (IPL)` 归 `Hoppy`，`Lager - American Amber / Red` 归 `Amber`。
  - `Stout/Porter`：所有 `Stout - *`、`Porter - *`。
  - `Wheat`：所有 `Wheat Beer - *`。
  - `Hoppy`：所有 `IPA - *` + `Pale Ale - American/English/Belgian` + `Lager - IPL`。
  - `Blond`：`Blonde Ale - American`、`Blonde Ale - Belgian`、`Kölsch`。
  - `Amber`：`Altbier`、`Red Ale - American Amber / Red`、`Lager - American Amber / Red`、`Red Ale - Irish`。
  - `Brown`：`Brown Ale - American/Belgian Dark/English`、`Mild Ale - English Dark/Pale`、`Old Ale`。
  - `Strong ale`：`Strong Ale - American/English/Belgian Dark/Belgian Pale`、`Quadrupel (Quad)`、`Barleywine - American/English`、`Red Ale - Imperial`、`Bock - Doppelbock/Eisbock`。
  - `Tripel`、`Dubbel` 各自单列。
  - `Lambic`：`Lambic - Traditional/Gueuze`；`Kriek`：`Lambic - Fruit`；`Faro`：`Lambic - Faro`。
  - `Saison`：`Farmhouse Ale - Saison/Bière de Garde/Sahti`。
  - `Christmas`：`Winter Warmer`、`Herb and Spice Beer`、`Pumpkin Beer`、`Chile Beer`。
  - `Low/No alcohol`：`Low Alcohol Beer`；`Fruitbeer`：`Fruit and Field Beer`。
  - `West Flanders ale`：`Sour - Flanders Red Ale`；`Flanders old brown`：`Sour - Flanders Oud Bruin`。
  - `Brett/cofermented`：`Brett Beer`、`Wild Ale`；`Scotch`：`Scotch Ale / Wee Heavy`、`Scottish Ale`；`Brut`：`Bière de Champagne / Bière Brut`。
- 映射是**语义判断**，不是官方对照；不同人可能把某些边界风格归到不同类。论文中应把映射表作为附录，并做“换一种映射是否改变结论”的敏感性说明。

**必须写进论文的方法学结论**：

1. **不要直接使用原始词频均值**。原始词频受“评论条数/评论长度”强烈混杂：全表每款酒总词频中位 384，但风格间差异巨大（Sahti 中位 13、Brut 26.5、Eisbock 34，而 Barleywine/IPA 可到 500+）。归一化后 `Sweet` 的 7.csv 相关从 0.338 升到 0.697，说明原始相关被评论量压制。
2. **推荐做法**：`p_ij = c_ij / Σ_k c_ik`，并剔除 `Σ_k c_ik < 50` 的行（剔除 380 行，保留 5,178 行，93.2%）；再按风格求均值。低评论量风格（Brut 仅保留 20/50、Faro 11/16）要单独标注不可靠。
3. **7.csv 比 4.csv 更适合做外部对照**：两者都是评论/词频体系，7.csv 的对应维度相关性普遍更高、更稳定；4.csv 是培训品评小组的强度评分，测量模型不同，归一化后相关性下降（Alcohol 0.540→0.257，Body 0.477→0.307）。
4. **稳健性**：全样本 Sour r=0.890，但去掉 7 个酸/野生风格（Lambic、Kriek、Faro、West Flanders ale、Flanders old brown、Brett、Fruitbeer）后，Sour r=0.606、Malty 0.624、Alcohol 0.608、Bitter 0.566、Sweet 0.514、Hoppy 0.759、Fruits 0.671（n=15）。说明相关性不只是“酸 vs 不酸”的二分，但酸啤家族贡献很大；**不能把风格级相关外推到逐酒个体**。
5. 这是 **22 个风格均值的生态相关**，不是 250 款酒的个体级相关；论文中必须写明 n=22、聚合层级、映射主观性，避免过度解读。

### 4.6 推荐的连接流程（可复现）

1. 读 `beer_data_set.csv`，按 §4.4 的互斥映射得到 `style_attach`。
2. 对每款酒计算 11 列总和 `T`；保留 `T ≥ 50`；计算 `p_ij = c_ij / T`。

## 5. 三个具体的论文用法

### 用法 1（Q1）：风格级外部先验 + 稳健性检验

**放在论文哪里**：Q1“缺失条件下的感官评分”之后，新增一小节“外部风格先验与稳健性”；或放在 Q1 的模型正则化部分。

**具体做法**：

- 用 §10 的 22×11 归一化原型矩阵 `P`，取与 Q1 目标语义相近的维度：`Bitter`、`Sweet`、`Sour`、`Hoppy`、`Malty`、`Alcohol`、`Spices`（`Fruits`/`Body` 相关弱，最多做弱先验；`Astringency`/`Salty` 不用）。是否属于 Q1 的约 40 维，以 `3.xlsx` 实际字段为准；`Body`/`Astringency` 属口感，可能不在 Aroma/Flavour 两套里。
- 外部值是词频比例，不是 0–6 分，**只能做排序/标准化对齐**：对每个维度在 22 个风格内做 rank 或 z-score，得到 `z_ext(s,d)`；把 Q1 预测的“风格均值”也转成 rank/z，计算一致性惩罚 `λ_d * (z_pred(s,d) - z_ext(s,d))^2`。
- `λ_d` 按外部相关强度设置：`Sour/Malty/Hoppy/Bitter/Alcohol/Sweet` 可用较大 λ；`Fruits/Body` 用 0 或很小 λ；并按风格样本量调节——附件只有 3–5 款的 Faro/Brut/Scotch/Flanders old brown 可以更强地向外部风格均值收缩，样本多的 Blond/Tripel 可以让数据主导。
- **注意**：Q1 的 40 维目标里，外部只覆盖 7 个左右的粗维度；这不是监督学习标签，不能替代 3.xlsx 的评分体系。它的作用是“防止小样本风格预测漂移”和“事后 sanity check”。

**论文产出**：

- 表：22 个风格 × 7 个维度的“本文预测均值 vs 外部词频均值”，附 Pearson/Spearman；报告加先验/不加先验的 Q1 指标变化。
- 图：22×7 的预测–外部热图或散点矩阵；突出 Faro/Brut/Scotch 等小样本风格。
- 敏感性：换映射、去酸啤家族、只用 7.csv/4.csv 两种对照，结论是否稳定。

**不能做什么**：不能声称“外部数据提供了 250 款酒的 0–6 标签”；不能把词频比例直接当 0–6 分回归目标。

### 用法 2（Q3）：风格原型、跨风格迁移方向与生成评价

**放在论文哪里**：Q3“风格条件生成”和“跨风格迁移”两小节。

**具体做法**：

- 用 §10 的 `P` 作为 22 个风格的**感官原型**。生成器输入风格 `s` 和隐变量 `z`，输出化合物谱 `x`；再用附件数据训练的“化合物→感官”代理模型 `g(x)` 得到感官画像 `ŷ`。损失写成：
  `L = L_recon + α · L_sensory(ŷ, P_s) + β · L_defect`，
  其中 `L_sensory` 用余弦距离或 rank 距离（因为外部是词频比例，不是绝对分数）；`L_defect` 约束 DMS/Diacetyl/4VG/trans-2-nonenal/Stale hops 不超阈值。
- **跨风格迁移**（Pils/Lager → Tripel）：用归一化原型之差构造软方向
  `Δ = P_Tripel - P_Pils/Lager`。
  按 §10 的数，方向大致是：`Alcohol +0.031`、`Sweet +0.043`、`Sour +0.067`、`Fruits +0.114`、`Spices +0.059`；`Bitter -0.058`、`Malty -0.128`、`Hoppy -0.069`、`Body -0.025`。迁移时把 `ŷ` 沿 `Δ` 推，而不是硬贴到 Tripel 原型；同时保持缺陷化合物不恶化。注意 `Sour` 的上升与直觉不完全一致，说明词频画像有噪声，建议只把方向一致且相关强的维度（`Alcohol/Sweet/Fruits/Spices ↑`，`Malty/Bitter/Hoppy ↓`）当约束，`Sour` 仅作观察。
- **稀有风格**：Faro（附件 3 款；Kaggle 过滤后 11 款）、Brut（4 款；过滤后 20 款）、Scotch（5 款；100 款）、Flanders old brown（5 款；49 款）用外部原型做条件目标/评价基准，可缓解附件样本太少导致的条件均值不稳定；但 Brut/Faro 评论量低，必须标注“低置信度原型”。
- **评价**：对每个风格计算生成画像 `ŷ` 与 `P_s` 的余弦相似度/rank 相关；对比“有条件 vs 无条件”“有外部原型 vs 无外部原型”“迁移前后”；报告缺陷化合物超阈值率。这样 Q3 不只有“看起来像”，还有可量化的风格一致性。

**论文产出**：

- 表：22×11 风格原型（§10）；Tripel/Pils/Lager/Kriek/Lambic 的雷达图或热图。
- 图：Pils/Lager→Tripel 的迁移方向图（`Δ` 的条形图）；生成前后感官画像对比。
- 表：跨风格迁移的缺陷化合物超阈值率 + 风格一致性指标。

**不能做什么**：外部数据没有化合物，**不能**直接监督 `x` 的生成，也不能声称“外部数据验证了化合物谱的化学合理性”。它只能验证/约束**感官画像**；化合物合理性仍要靠附件 `1.csv/2.csv` 与化学阈值。

### 用法 3（全文/讨论）：外部效度 + 感官词典桥接

**放在论文哪里**：数据质量/外部效度小节，或讨论部分“外部数据与局限性”。

**具体做法**：

- 把 §4.5 的跨数据集风格级相关表作为**外部效度证据**：22 个风格标签不是随便分的，附件 `7.csv` 的 `taste_sour`、`taste_bitter`、`aroma_malty`、`aroma_hoppy`、`taste_sweet`、`taste_alcohol` 等均值与独立来源的 Kaggle 词频画像方向一致（Sour 0.89、Malty 0.79、Hoppy 0.77、Bitter 0.75、Alcohol 0.72、Sweet 0.70）。这可以回应题目强调的“数据真实、噪声合理”。
- 用 Kaggle 的 11 维词表作为**感官词典桥**，解释附件 186 个 Ratebeer 描述符（`7.csv`）和 50 个培训品评维度（`4.csv`）之间的关系：例如 `aroma_hoppy/palate_hoppy/taste_hoppy → Hoppy`，`aroma_malt/palate_malt/taste_malt → Malty`，`taste_sour → Sour`，`taste_bitter → Bitter`，`taste_sweet → Sweet`，三类 `*_alcohol → Alcohol`，`anise/clove/coriander/herb → Spices`。在论文中给出这张 crosswalk 表，说明“为什么 Q1/Q3 选这些感官轴、为什么某些轴不可靠”。
- 用外部原型做 Q3 的**基线**：对每个风格，比较“只用附件数据估计的风格均值”与“附件+外部原型”的一致性；如果差异大的风格恰好是附件样本少的风格（Faro/Brut/Scotch），就是外部先验最有价值的地方。
- 讨论**数据集偏差**：Kaggle 是 BeerAdvocate 的“top-rated”酒，最多 50 款/风格，英语评论词频；存在选择偏差、语言偏差、评论量偏差。它适合做风格级方向性校验，不适合估计绝对感官强度或个体分布。

**论文产出**：

- 表：跨数据集风格级相关（全样本 / 去酸啤家族 / leave-one-style-out 范围）。
- 表：11 维词表 ↔ 附件感官列的 crosswalk。
- 讨论：外部数据能支持什么、不能支持什么；明确“生态相关，不是个体级因果”。

## 11. 最终结论

- **数据获取：成功**。5,558×21 主表 + 词表；CC BY 4.0；文件校验和已记录；原始数据在 `data/external/`，不进 git。
- **数据性质：评论词频，不是化合物，不是 0–6 评分**。这是论文中必须反复说明的边界。
- **连接层级：只能到 22 个风格**。附件没有酒名/酒厂，Kaggle 没有条码；ABV 匹配歧义过大，不能逐酒合并。
- **论文价值：中等偏上，但定位是辅助**。最强的用法是 Q3 的风格原型/迁移方向/生成评价，以及全文的外部效度表；Q1 可做风格级先验；Q2 不能直接支撑。
- **若要把外部数据用得更深**：需要拿到附件 250 款酒的酒名/酒厂（或完整条码→酒名映射），或者拿到含化合物的另一份公开数据；仅靠这份 Kaggle 数据，无法做化合物级增强。
